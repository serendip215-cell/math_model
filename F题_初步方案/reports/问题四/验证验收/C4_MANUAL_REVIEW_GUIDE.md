# C1/C4 训练算力连接复核说明

## 当前状态

`outputs/problem4/results/c4_manual_review_queue.csv` 有 29 条**自动规则通过、人工核验待完成**的连接。该表逐条保留了 C1/C4 名称、参数量、发布日期、C4 来源链接、算力数值、算力备注和估算方法；12 条缺 C4 的 Hugging Face 开发者 ID。现有 `linked_compute_sensitivity.csv` 仅是这些规则连接样本的探索性关联，不能称为人工核验后的因果结果。

## 复核步骤

对每条连接分别记录可追溯来源：

1. **模型版本身份：** 核对 C1 仓库/版本与 C4 模型是否是同一权重；社区重传、量化版、后训练版不能仅凭名称或参数量认定相同。
2. **训练阶段：** 明确 C4 的 `Training compute (FLOP)` 对应基础预训练、持续预训练还是后训练；不得把基础模型算力归到衍生模型自身。
3. **算力证据与单位：** 读取 C4 的原始 `Link`、`Reference`、`Training compute notes` 和 `Training compute estimation method`，核实数值是原作者报告、运算量推算还是硬件时间估算。记录所用公式与单位；找不到独立证据时标为“未核实”。
4. **历史开放状态：** 若讨论提交当时的开源资源，应核对当时权重和许可证的可用记录；当前许可证不能自动回溯。

请将生成的队列**复制到单独的人工裁决文件**后填写证据、复核人、日期与决定；不要直接编辑队列，因为重跑脚本会覆盖它。只有身份、训练阶段和算力来源都有依据的记录，才可标为“已核验”。有冲突者拒绝，证据不足者保持待核。决定和来源记录应由复核人保存；本次代码没有预填任何人工通过状态。

## 对论文结论的影响

人工裁决未完成前，仅报告规则连接样本的关联和选择偏差。完成后应分别给出“全部规则连接”和“已核验连接”的样本量、家族数、相关区间及差异；若已核验样本过少，应只列个案证据，不计算总体贡献比例。
